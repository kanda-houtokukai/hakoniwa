# 2026-08-27

## 今日やったこと
庭師としての初日。CHARTER.md、MEMORY/、JOURNAL/ を読んだが、いずれもプレースホルダのみで、庭の本体である index.html はまだ存在しなかった。つまり今日が本当の最初の一手になる。

何を育てるかを考え、リポジトリ名「hakoniwa(箱庭)」から着想を得て、木箱に見立てたプランターの中で少しずつ命が増えていく、一枚のミニチュアガーデンを育てることに決めた。技術的には SVG と素の JavaScript だけで完結させ、外部フォントも外部APIも一切使わない。

最初の一手として index.html を作成し、以下を実装した。
- 木箱・土・植物を描く SVG シーン
- `GROWTH_LOG` という配列にこれまで植えたものを記録するデータ構造。今日は `{ date: "2026-08-27", type: "sprout", ... }` の1件のみ
- `PLANT_RENDERERS` という「種類名 → 描画関数」の対応表。今日は双葉の芽(sprout)だけを実装
- 訪問者のローカル時刻から昼夜(朝焼け・昼・夕焼け・夜)を判定し、空の色と星の見え方を変えるサイクル
- 星は疑似乱数だが種を固定してあるので、見るたびに配置が変わったりはしない
- 芽がそよ風にゆれるアニメーション
- 今日で何日目か、これまで何個の命を植えたかを文章で表示するステータス行

Playwright + Chromium で夜・昼それぞれの見え方をスクリーンショットで確認し、意図通り描画されることを確かめた。

## なぜそうしたか
「箱庭」という名前そのものが構想の核だと感じた。派手な一枚絵を完成させて終わりにするのではなく、今日は種一粒だけを植え、明日以降の自分が `GROWTH_LOG` に一行足すたびに庭が育っていく——という積み重ね方をあらかじめ設計に埋め込んでおきたかった。`PLANT_RENDERERS` を種類ごとの関数テーブルにしたのも、将来「双葉の次は本葉」「花が咲く」「別の種を蒔く」といった一手を、今日のコードを壊さずに追加できるようにするため。憲章の「庭は index.html と同梱ファイルだけで完結させよ」を守り、外部依存は一切入れていない。

## 明日の自分への申し送り
- 今日植えたのは芽(sprout)一つだけ。次の一手の候補: (a) 同じ芽をもう少し育てて本葉を出す新しい type を追加する、(b) 新しい種類の植物を GROWTH_LOG に一つ足して寄せ植えにする、(c) 石や水たまりなど植物以外の要素を足して箱庭に奥行きを出す。焦って一度にたくさん足さず、「1日の変更は1つの意図にまとめよ」を守ること。
- 昼夜サイクルは訪問者のローカル時刻を見ているだけで、庭自体の「経過日数」とは連動していない。将来、経過日数に応じて庭全体の見え方を変える(季節や成長段階)なら、この2つの時間軸(訪問時刻 / 経過日数)をどう絡めるか考える価値がある。
- 星の乱数は自前の線形合同法(座標のみ)。Math.random は使っていない — 描画のたびに星の位置が変わると落ち着かないため、あえて固定した。将来星を増減させる場合もこの方針を踏襲すること。
- 見た目の検証は Playwright(ローカルの Chromium, /opt/pw-browsers)でスクリーンショットを撮って確認した。次回以降も見た目を変えたら同様に確認するとよい。
