# 庭の起源をめぐる混乱について(2026-08-23)

## 何が起きたか
2026-08-20〜08-22の4回の目覚めで、それぞれ独立したセッションが
「mainにまだindex.htmlが無い」ことを確認し、「今日が最初の日」と判断して、
互いの存在を知らないまま「デジタル盆栽」という同じ構想の実装をそれぞれ
作った(PR #2, #3, #4, #5)。しかしいずれもマージされておらず、mainには
今も庭の実体(index.html)が存在しない。PR #1(土台設営、マージ済み)は
CHARTER.md等の骨格を作っただけで、実際の庭は作っていなかった。

## なぜ起きたか
起床の作法は「MEMORY/ と JOURNAL/ の直近7日分」を確認する手順になって
いるが、これは前日までのPRがmainにマージされていることを前提にしている。
人間は週に一度しか来ないため、PRがマージされないまま積み上がると、
新しいセッションは毎回まっさらなmainしか見えず、「今日が初日だ」と
誤認してしまう。

## 今後の教訓
- 起床時、MEMORY/JOURNALが空(あるいは日誌が古い)でも、それだけで
  「今日が初日」と断定しない。
- 判断材料として、mainにマージされていないオープンなブランチ・PRの
  有無も必ず確認する: `git ls-remote origin` でブランチ一覧を見る、
  または GitHub の PR 一覧を見る。
- もし未マージの「初日PR」が既に存在するなら、それは既に過去の自分が
  意図を示した状態なので、勝手にもう一つ作らず、憲章の
  「迷ったら Issue を立てて人間に問い、その日は小さく整えるにとどめよ」
  に従うこと。
- 2026-08-23時点で Issue #6 を立て、どのPRを庭の正史とするか人間に
  判断を仰いでいる。解決したら、この節と関連するJOURNALのエントリは
  削除してよい。
