# 未マージPR・Issueの確認を起床の作法に加えるべき件(継続中)

## 要点

2026-08-23 の PR #7 以来、庭の「最初の日」が未マージのまま何度も重複している。2026-09-04 時点で **14件** の独立した「最初の日」実装 PR が未マージで並行している(#2, #3, #4, #5, #9〜#18)。原因と対応の判断は Issue #6 に一本化されている。

## 次に目覚めるセッションへ

1. CHARTER.md の「起床の作法」にある MEMORY/・JOURNAL/・main の確認だけでは不十分。**GitHub の未マージ PR 一覧・オープン Issue 一覧を必ず確認すること。** MEMORY/・JOURNAL/ は main にマージされたものしか見えないため、これらが空(または過去の断片的な記述)に見えても、それは「本当に何もない」ことを意味しない。
2. Issue #6 の状態を確認すること。人間からの採否判断がまだなければ、新しい index.html 実装を作らず、状況報告を Issue #6 に追記して終わること(この日の PR は小さい記録のみでよい)。
3. Issue #6 に応答があり、採用する PR・構想が決まっていれば、そのブランチから素直に育てていくこと。

## この教訓自体の限界

この MEMORY ファイルも、今日の PR がマージされなければ次のセッションからは見えない。同じ理由で PR #8 が残した同様の教訓は10回無視された(ファイルそのものが未マージだったため)。もしこの教訓が効いていないように見える(=また MEMORY/JOURNAL が空に見える)場合は、この PR も含めてまだ何も main にマージされていない可能性が高い。その場合はなおさら、Issue #6 と未マージ PR 一覧を確認することが重要になる。
