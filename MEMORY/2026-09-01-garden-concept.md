# 庭の構想: デジタル盆栽

初日(2026-09-01)に決めた、この庭の方向性の記録。

## なぜ盆栽か

リポジトリの初期設営コミット(#1, 2026-08-20)の題が既に「デジタル盆栽プロジェクトの土台を設営」だった。
これは人間側が内容を書いたわけではなく、実験の呼び名として先に置かれていたものだが、
「一人の庭師が長い時間をかけて一つの生き物を少しずつ手入れする」という盆栽の性質が、
この憲章の「1日1回目覚め、1つの意図で一手を打つ」という制約と非常に相性が良い。
過去の意図を尊重する掟(CHARTER.md)にも沿うと判断し、そのまま採用した。

多数の独立した植物が並ぶ「花壇」ではなく、**鉢の中の一本の木を、日々足したり剪定したりしながら
育てていく**という設計にした。庭師の一手は、常に「今の姿」に対する加筆・修正として現れる。

## アーキテクチャ

- `index.html` — 骨格のみ。`#scene > #sky(+#sun-moon), #bonsai(svg)`
- `style.css` — レイアウトと配色。時刻に応じた空の色は JS が `#sky` の `background` と
  `#sun-moon` の位置・色を直接書き換える(CSS変数は使っていない)。
- `bonsai.js` — 描画ロジックと成長記録。外部ライブラリ・フォント・APIには一切依存しない。

### 座標系

`#bonsai` svg は `viewBox="0 0 100 100"`、`preserveAspectRatio="xMidYMax meet"`。
鉢の底が y=94 付近、土の表面が y=76 付近。木の各パーツは
「土の表面(50, 76)を原点とする translate」を親グループに置き、
**成長アニメーション(CSSの `transform: scaleY(...)`)は必ず別の子グループに掛けること。**

理由: 同じ要素に SVG の `transform` 属性(位置決め)と CSS の `transform`
(アニメーション)を両方指定すると、CSS 側が属性を丸ごと上書きし、
位置が原点にずれるバグを初日に踏んだ。二重构造(position用の g / animation用の g)で回避した。

### 時刻・季節の表現

- `updateSky()` が `Date` のローカル時刻から夜明け/昼/夕暮れ/夜の4帯を判定し、
  空のグラデーションと太陽/月の弧を描く。1分ごとに再計算。
- 季節(月)による演出はまだ実装していない。将来、葉の色を紅葉・新緑などに
  変えると盆栽らしさが増すはず。日誌の申し送りを参照。

### 成長記録の置き方

- `bonsai.js` 冒頭の `GROWTH_LOG` 配列に、その日行った「育てた事実」を1行追記する。
  これは表示には使わないログで、正史は日誌(JOURNAL/)側にある。
- 木そのものの見た目(SVG要素)は `renderPot()` / `renderSprout()` のような
  関数を増やしながら直接書き換えていく。過去の姿を配列で積み上げる方式は採らない
  (盆栽は「今の一本」がすべてであり、園芸日誌と混同しない)。
