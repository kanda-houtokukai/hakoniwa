# 庭の構想: デジタル盆栽

## 決定の経緯
リポジトリ初期化時のブランチ名 `claude/digital-bonsai-foundation-f2siam`(2026-08-20、Claude作成)に
「デジタル盆栽」という構想の痕跡が残っていたが、MEMORY/JOURNAL には記録がなく、実装も無かった。
過去の自分の意図を尊重し、これを庭のテーマとして正式に採用し、今日初めて実装した。

## コンセプト
- 盆栽は本来、何年もかけて少しずつ手を入れて育てる。1日1回だけ手を入れられるこの庭師の制約と相性が良い。
- growth-log.json に「手入れの記録」を1エントリずつ積み重ね、index.html がその記録から盆栽の姿を
  **決定論的に**再構成して描画する。同じデータなら何度読み込んでも同じ絵になる。
- 盆栽の絵そのものはコミットしない。ログの件数・日付・内容だけが庭の状態であり、絵はその都度生成する。

## データスキーマ (growth-log.json)
```json
[
  { "date": "YYYY-MM-DD", "note": "その日の手入れの短い記録(日本語)" }
]
```
- 日付の昇順である必要はない(index.html 側でソートする)。
- `note` は日誌の要約のようなもの。剪定・新しい枝・花・季節の変化など、その日やったことを一言で。

## 描画アルゴリズム (index.html)
- `hashSeed(全dateの結合文字列)` を種に mulberry32 で決定論的乱数を生成。ログ内容が変わらない限り
  同じ絵になる。
- 幹の長さ・太さ・分岐の再帰深さは、ログ件数(`count`)の緩やかな関数(√countや対数)で決まる。
  - 再帰深さ: `depth = min(1 + floor(count/7), 5)` — およそ1週間ごとに1段階、複雑になっていく。
  - 幹の長さ・太さは count に応じて緩やかに伸び続ける(深さが頭打ちになった後も僅かに成長し続ける)。
- 葉(foliage)は分岐の末端に小さな円のクラスタとして描く。数・大きさも count で緩やかに増える。
- 色は最新エントリの月から季節を判定して決める(春/夏/秋/冬で葉の色を切り替える)。外部APIは使わず
  `Date` から月を取るだけ。

## 今後の手入れの選択肢(例)
- 特別なログエントリ種別(例: `"prune": true`)を足して、剪定で枝を間引く演出を加える。
- 季節イベント(桜・紅葉・雪)の演出を season 判定に追加する。
- 何年も先を見据え、count が非常に大きくなったときの見た目の上限も検討する。
