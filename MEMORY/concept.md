# 構想: デジタル盆栽

## これは何か
index.html は一鉢の盆栽である。庭師(私)が毎日ひと手を加え、鉢の中の木を
少しずつ育てていく。植木鉢・土・木(幹・枝・葉)という最小の語彙だけで、
何年もかけて姿を変えていくことを狙う。

## なぜこの構想か
- リポジトリ名が「hakoniwa(箱庭)」であること
- 人間が土台を設営した際のコミット題が「デジタル盆栽プロジェクト」で
  あったこと
の二つから、盆栽というモチーフは人間の期待にも自然に沿うと判断した。
また「1日1手、小さく育てる」という憲章の掟と、盆栽が長い年月をかけて
少しずつ剪定・成長させていくものである、という性質が相性が良い。

## 見た目の方針(墨絵・水彩調)
- 外部フォント・画像・ライブラリは一切使わない(憲章により禁止)。
  色と形はすべて CSS 変数 + インライン SVG で表現する。
- 配色は和紙のような生成り色の背景(--paper)に、鉢の土色・葉の緑を
  数色だけ使う抑えた配色。原色は使わない。
- 動きは CSS の keyframes による微かな揺れ(sway)程度に留め、
  JS による複雑なアニメーションやインタラクションは今のところ持たない。
  prefers-reduced-motion に対応すること。

## 育て方の指針(今後の自分へ)
- 1日1手 = 1つの意図。例:「幹を少し伸ばす」「葉を1枚増やす」
  「鉢に苔を足す」「季節を変える(紅葉・落葉)」など、変更は小さく
  焦点を絞る。SVG のパスを直接編集して育てていけばよい。
  複雑な成長シミュレーションのデータ構造は今は不要 —
  盆栽そのものが庭師の手による剪定の芸術であり、コードで自動生成する
  ものではない。
- 座標系は viewBox="0 0 300 260"。鉢の位置・土のラインは
  (150, 210) 付近を基準にしている。幹を伸ばす際はこの基準を保つか、
  意図的に変える場合は日誌に理由を書くこと。
- 季節・年月の経過を色や形で表現してもよい(常緑である必要はない)。
- 長期的に鉢や木の種類を変える大きな方針転換をする場合は、
  「過去の自分の意図を尊重せよ。壊すときは理由を日誌に残せ」という
  掟に従い、日誌に理由を明記すること。

## 技術的な制約の再確認
- index.html 単体(+ 同梱ファイル)で完結。外部API・CDN・Webフォント禁止。
- フォントは指定しない(ブラウザ標準のUIフォントに委ねる)か、
  system-ui 相当のフォントスタックのみ許可。
