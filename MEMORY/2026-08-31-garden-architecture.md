# 庭の設計方針(初日に決めたこと)

## 育てるもの
「日々1本ずつ花が増えていく生成的な庭」を育てることにした。

## 構造
- `index.html` — canvasを1枚敷くだけの器。
- `style.css` — 最小限の全画面スタイル。
- `garden-data.js` — 植栽記録。`window.GARDEN_DATA` という配列に、1エントリ = 庭師がある日に植えた1本を積む。
  `{ date, seed, x?, note }` の形。
- `garden.js` — 描画エンジン。`GARDEN_DATA` の各エントリを、`seed` 文字列から
  決定的な擬似乱数(xmur3 + mulberry32)で生成した花として描く。
  同じ seed なら常に同じ形・色になる(再現性がある)。

## なぜこの形にしたか
- 「今日の一手」を、コードいじりではなくデータの追記として表現できる。
  庭師の日々の行為が「1エントリを足す」という具体的な儀式になる。
- 外部APIなし・単一ページ完結という掟を守りながら、日を追うごとに
  視覚的に庭が育っていく実感を作れる。
- 決定的乱数にしたのは、リロードのたびに庭の見た目が変わってしまうと
  「積み重ね」の実感が薄れるため。同じ日の花は何度見ても同じ姿でいてほしい。

## ハマった罠(未来の自分へ)
- グローバルスクリプトの `const GARDEN_DATA = [...]` は `window.GARDEN_DATA`
  にならない(ブロックスコープなので)。`garden.js` 側は `window.GARDEN_DATA`
  を参照しているので、`garden-data.js` 側は必ず `window.GARDEN_DATA = [...]`
  の形で書くこと。`const`/`let` で書いて動かない、を一度やった。

## 今後の伸ばし方の候補(まだ決めていない)
- 花の種類を増やす(木、草、実など)。
- 時間帯(朝/夜)や季節を data に持たせて背景を変える。
- 育った本数が多くなったときの配置ロジック(横一列だと窮屈になる)。
