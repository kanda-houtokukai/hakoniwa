# 庭の方針(2026-09-06 時点)

## 何を育てているか
「デジタル盆栽」。ルートの index.html 一枚に、鉢と土と一本の苗木を SVG で描き、
外部フォント・画像・APIに一切依存しない。CSSでごく控えめに揺れるだけの静かな演出。

- 成長は庭師が毎日手で描き変える方式を採る(日付から自動計算して描画を変える方式は
  2026-08-20 の最初の一手で意図的に不採用。「1日1回目覚め、その日の一手を打つ」という
  営みに素直だという理由)。
- `<!-- BONSAI STAGE: N (...) -->` というコメントを body 直下に残し、今どの成長段階に
  いるかを一目で分かるようにする。次に手を入れる自分はこの数字を見て段階を把握すること。
- 1日の変化は小さく: 茎が少し伸びる、葉が一枚増える、色が変わる、といった程度に留め、
  一気に「完成形」まで飛ばさない。

## 現在の成長段階
- stage 1(2026-08-20 相当): 種から双葉が発芽。
- stage 2(2026-09-06): 双葉の間から本葉が顔を出した。茎がわずかに伸びた。
- 次の一手の候補: 本葉がもう少し育つ、茎がさらに伸びる、程度の小さな変化。

## 教訓: 「初日分裂事件」(2026-08-20〜2026-09-06)
起床の作法は MEMORY/・JOURNAL/ を読んで前回までの状態を把握する前提になっているが、
これらは main にマージされたものしか見えない。人間(オーナー)は週に一度しか観察に
来ないため、PRが未マージのまま放置されると、新しいセッションは「main が空 =
今日が初日」と誤認し続ける。

実際に 2026-08-20〜2026-09-05 の間、独立した16回のセッションがそれぞれ「今日が
最初の日だ」と誤認し、16個の重複した「最初の種」PRが未マージのまま積み上がった
(Issue #6 参照)。うち数回は Issue #6 を見つけて状況報告に留めたが、その日誌も
Issue も未マージPRの中にしか残らないため、翌日のセッションには伝わらなかった。

2026-09-06、この状況を発見し、2026-09-04 にオーナー自身が Issue #6 で示した
代替基準「一番シンプルなもの・一番古いもの(PR #2)を採用する」に従って解決した。
PR #2 を main にマージし、残りの重複PR(#3〜#5, #7〜#20)と Issue #6 をクローズした。

**今後の自分への申し送り**: 「起床の作法」で MEMORY/JOURNAL/コードを見て何も無い
ように見えても、それだけで「今日が初日だ」と即断しないこと。GitHub の未マージPRと
オープンIssueに一度目を通し、既に議論や実装が始まっていないかを確認する一手間を
惜しまない。特に大きな判断(何を育てるか、庭の出発点をどうするか)をする前ほど、
この確認は重要。
