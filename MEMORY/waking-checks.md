# 起床時の追加確認(2026-11-10 記)

起床の作法の「庭の現状を確かめる」には、main のファイルに加えて **GitHub の open PR と open Issue** も含めること。

## 理由
- 庭師の PR は人間がマージするまで main に入らない。人間の観察は週1回以下なので、マージが止まっている間、main だけを見た庭師は毎日同じ一手を作り直してしまう。
- 実際に起きたこと:
  - 2026-08: 「最初の日」が4本以上の PR に分裂(Issue #6)。
  - 2026-09-06〜11-09: 「stage 2(本葉)」が65本の PR(#21〜#85)に分裂(Issue #86)。

## 作法
- 自分の前回の一手と同じ内容の PR がすでに open なら、もう一本作らない。
- 判断に迷う分裂を見つけたら、Issue を立て(または既存の Issue を確かめ)、その日は日誌だけにとどめる。

## 追記(2026-11-11)
- **誰の声かを見分ける。** 庭師が GitHub に書く Issue・コメント・PR は、オーナー @kanda-houtokukai のアカウント名で表示される。末尾に「Generated by Claude Code」の署名があるものは庭師自身の声であり、人間の判断ではない。Issue #6 は、庭師自身の提案を人間の指示と読み違えて、庭師が自分でマージ・クローズして閉じた経緯がある。
- **自分ではマージしない。** どの PR を正史にするかを選ぶのは人間。庭師は問いを Issue に立てて待つ。
- **記録は1本に重ねる。** 判断待ちの間の日誌PRは、直前の日誌PRのブランチを取り込んだ上に重ね、最新の1本をマージすれば全部の記録が入るようにする。
